**Дата:** 2026-09-01 · **Статус:** утверждён
**Область:** Phase 1.2 (свой датасет + fine-tune) + Phase 7 (HITL — реальный FC)
+ подготовка Phase 8 (полёты). Всё, что нужно сделать и купить, до первого

SHM-кольцо кадров + шина Zenoh + 8 systemd-сервисов, детектор 27 FPS,
замкнутая петля на ArduPlane SITL, soak 30 мин без падений. Формальные
фазы ROADMAP 2–6 закрыты с превышением KPI (29.5 мс против целевых 60;
27 FPS против 15).

## §0. Определение и ворота готовности

```
Стадия 1 (готово): стенд + SITL          Стадия 2 (эта):             Стадия 3:
───────────────────────────────────       ─────────────────────→      ─────────
камера USB → SHM → NPU → шина       1.2 свой датасет + модель        MIPI-камера,
командир → SITL-планер (симуляция)  7   реальный FC на столе (HITL)   dmabuf,
```

**Жёсткое правило:** полёт запрещён, пока ВСЕ пункты раздела F
(Flight Readiness) в [SAFETY.md](SAFETY.md) не пройдены. HITL-этап
не имеет этого ограничения (моторы без пропеллеров / планер на столе).

**Ворота между этапами Стадии 2:**

| Ворота | Условие перехода дальше |
|---|---|
| G1 → HITL | fine-tune модель: mAP@0.5 ≥ 0.85 на val классов стенда; ≤10 дет/кадр на живом видео |

| Полёт | tethered → с safety-pilot → только потом автономные сегменты |

## §1. Выбор полётного контроллера (решение за тобой, рекомендация — моя)

Требования проекта: ArduPilot **Plane** (самолётный тип), MAVLink2 по UART
к компаньону, ≥2 свободных UART (TELEM→OPi5, второй → GCS/логгер),
надёжный SD-лог (расследование инцидентов), внешняя GPS+магнитометр.

| Критерий | **Matek H743-Wing** ⭐ | Holybro Pixhawk 6C | SpeedyBee F405 Wing |
|---|---|---|---|
| Цена (плата) | ~$65 | ~$200 (без GPS) | ~$40 |
| MCU | STM32H743 @ 480 MHz | STM32H743 @ 480 MHz | STM32F405 @ 168 MHz |
| UART | **7** | 6 (+CAN) | 4–5 |
| SD-лог | ✅ встроенный | ✅ | ❌ (только blackbox-flash) |
| Барометр | 1 (внутр.) + разъём внеш. | 1 + внеш. стандарт | 1 |
| BEC на плате | 2 (5V/5A + 10V) | нет (внеш. модуль) | 1 |
| Вес | 35 г | 99 г (кейс) | 20 г |
| Сообщество ArduPilot-Plane | **dev-board, активная поддержка** | стандарт индустрии | среднее |
| Форм-фактор | wing-специфичный | Pixhawk-стандарт (PEXT) | wing |

**Рекомендация: Matek H743-Wing** — оптимум цена/надёжность/функции для
ArduPilot-самолёта; у(dev)-команда ArduPilot активно тестирует на этой
плате. Pixhawk 6C — если нужен индустриальный стандарт и бюджет позволяет.
SpeedyBee (текущий референс в доксах) — рабочий минимум, но 4 UART и
отсутствие SD-лога осложнят одновременную связку компаньон+GCS+лог.

**Комплект к FC (независимо от выбора):**
- GPS+магнитометр: **Matek M10Q-5983** (~$28; QMC5983 + M10, компакт) или
  Holybro M9N (~$35; для Pixhawk). Мелочь: вынос GPS на антенную мачту /
  хвост — подальше от OPi5 (NPU-помехи) и силовых проводов.
- Приёмник RC: см. §9 (ELRS).
- Прошивка: **ArduPilot Plane, latest stable** (не beta!);
  Matek — загрузчик через Mission Planner / SD-карту.

**Параметры ArduPilot (актуализирую в HARDWARE_SETUP после выбора):**
```
SERIAL1_PROTOCOL = 2      # MAVLink2 (TELEM1 → OPi5)
SERIAL1_BAUD = 57         # 57600 для стола (HITL); 921600 опция позже
SERIAL2_PROTOCOL = 2      # MAVLink2 (TELEM2 → GCS)
BRD_SER1_RTSCTS = 0       # без flow control к CP2102
ARMING_CHECK = 1          # все проверки
```

**Действие после выбора:** фиксируем ADR D-018 (миграция референса с
SpeedyBee на выбранную плату) и я обновляю SAFETY.md F1 +
HARDWARE_SETUP.md под неё.

## §2. Связь Orange Pi 5 ↔ FC (проводка до пина)

### Вариант A — USB-TTL адаптер (рекомендация для HITL)

**Купить:** CP2102 (модуль с 6 пинами, 3.3V логика) — ~$2. Подключение
без пайки, нулевой риск для GPIO OPi.

```
FC TELEM1          CP2102          Orange Pi 5
─────────          ──────          ───────────
TX  ─────────────► RX
RX  ◄───────────── TX
GND ─────────────► GND ──────────► USB-порт
(5V — НЕ подключать!)
```

| FC-пин | CP2102-пин | Примечание |
|---|---|---|
| TELEM1 TX | RX | **Кросс!** TX→RX — типовая ошибка №1 |
| TELEM1 RX | TX | Кросс обратно |
| TELEM1 GND | GND | Общий GND **обязателен** |
| TELEM1 5V | — | НЕ подключать: CP2102 питается от USB |

Порт на OPi5: `/dev/ttyUSB0` (проверить: `dmesg | tail` после втыка).
Права: `sudo usermod -aG dialout orangepi` (однократно).

Запуск fc-bridge: `fc-bridge --adapter ardupilot-mavlink \
  --endpoint serial:/dev/ttyUSB0:57600 --bus tcp/127.0.0.1:7447`.
(уже поддерживается — mavlink-крейт с transport-serial… **мелочь для
проверки**: serial-transport включён в features — если нет, добавлю.)

### Вариант B — GPIO-UART OPi5 (для полётной конфигурации, позже)

Pins 8 (TX) / 10 (RX) GPIO-разъёма, `/dev/ttyS*` (номер зависит от
оверлея). Требует включения UART-оверлея в armbian-config/DT и проверки
уровней (OPi5 3.3V — совместимо с FC 3.3V TTL, но проверить осцилллом
при первом включении). Отложить до лётного этапа — на столе CP2102 проще
и безопаснее.

**Мелочи-грабли (все реальные):**
- Кросс TX/RX — симптомы: телеметрия пустая, dmesg чистый → перекинь провода
- Нет общего GND — симптомы: мусор в потоке, обрывы → добавь GND-провод
- Длина: стол <30 см — ок; в планере >50 см — витая пара + экран
- CP2102 бывает с поддельным чипом (не работает при 921600) — для 57600 достаточно любого

## §3. Питание

### Стенд (HITL)

```
3S/4S LiPo ──► предохранитель 5A ──┬─► BEC #1 5V/5A ──► FC (по схеме платы)
                                    └─► BEC #2 5V/4A ──► Orange Pi 5 (USB-C
                                        или GPIO-пины 2/4/6 = 5V + GND)
```

- **OPi5 тянет ~2.5–3 A пик** (NPU full-load + USB-камера + вентилятор).
  BEC 5V/4A минимум. Хорошие: Matek mROD/5A, Holybro 5V/5A, или любой
  5V≥4A SBEC. **Купить:** BEC 5V/4A+ — ~$8.
- **Не питай OPi5 от BEC платы FC** — просадки при NPU-пиках →
  brownout-рестарты (наш systemd Restart=always спасёт, но потеряем сессию).
- Предохранитель на входе LiPo (5A blade) — мелочь за $1, спасает проводку.
- Мелочь: измерю фактический ток OPi5 под NPU-нагрузкой софтом
  (`/sys/class/power_supply/*` или USB-метр) до финального выбора БЭК.

### Полётная конфигурация (Phase 8)

Двойное питание: основной BEC + резервный (диодная сборка ORing на
Matek-платах встроена). Отдельная Li-ion 18650×2 (7.4V→5V BEC) для
компаньона — развязка от силовой traction-батареи. Детализирую при
переходе к полётам.

## §4. Охлаждение (закрытие KNOWN_ISSUES #13)

Факт из soak (§22.2): NPU 83–87 °C при непрерывном инференсе без
охлаждения. Цель: **≤80 °C sustained при 30-мин full-load**.

**Купить (заказ ~неделя, ~$10 суммарно):**

| Позиция | Спецификация | ~Цена |
|---|---|---|
| Радиатор | Профиль 40×40×12 мм (или 45×45), пазы под вентилятор | $3 |
| Термопрокладка | 1 мм, 40×40 (не паста — между SoC и радиатором зазор) | $2 |
| Вентилятор | 5V, 40×40×10 мм, 3-pin (сигнал тахо — опция мониторинга) | $3 |
| Питание вент. | От USB-порта OPi5 (5V) или BEC #2 | — |

Сборка: термопрокладка на RK3588 (снять штатную пластину-экран при
наличии), радиатор, вентилятор сверху, продув вниз на плату.
Софт-страховка уже в коде: троттлинг при ≥85 °C (D-017, `--throttle-temp`).
**Критерий приёмки:** повторный 30-мин soak с охлаждением → все зоны ≤80 °C.

## §5. Камера — финализация для Стадии 2

**Остаёмся на Vitade AF USB (MJPG)** — проверена в композиции (M4/M6/soak).
PS Eye — тестовый инструмент (не для полёта: rolling shutter, 60 °C нагрев).
MIPI CSI + dmabuf — Стадия 3.

**Купить/сделать для HITL:**
- Крепление камеры с виброразвязкой: силиконовые/резиновые стойки
  (уплотнители M3 силикон, ~$2) — крепим к планеру/стенду
- Мелочь: фокус Vitade фиксированный — проверить резкость на 10–30 м
  (съёмка таблицы/дачного домика) до датасет-сессий; если мыльно на
  нужной дистанции — рассмотреть камеру с ручным фокусом (Arducam
  OV9782 global-shutter — уже проверена у нас, но YUYV-потолок 32 FPS
  на PS Eye-драйвере; на Vitade MJPG 720p@30 достаточно для Stage 2)

Вибро-риг (F3 SAFETY): дрель/шейкер + камера на стойках → снять 2 мин,
проверить детекции сохраняются (скрипт сделаю).

## §6. Датасет + fine-tune (Phase 1.2)

**Разделение работ: ты собираешь и маркируешь, я строю конвейер и обучаю.**

### 6.1 Классы (из ТЗ стенда)

| id | Класс | Англ. label | Пример-референс |
|---|---|---|---|
| 0 | Палатка | `tent` | армейская/туристическая 2–4 места |
| 1 | Ящик | `box` | деревянный/пластиковый ящик 0.5–1 м |
| 2 | Бензовоз | `fuel_truck` | автоцистерна (в т.ч. армейская) |
| 3 | Джип | `jeep` | внедорожник типа УАЗ/Hummer |

### 6.2 Протокол съёмки (твоя часть, ~2–3 дня)

| Параметр | Требование |
|---|---|
| Разрешение видео | 4K или 1080p (Vitade → телефон/экшн-камера тоже ок для сбора) |
| Высоты | 5 м / 15 м / 30 м / 50 м (лестница, холм, коптер — что доступно) |
| Дистанции до цели | 10 / 30 / 60 / 100 / 150 м |
| Углы (элевация камеры) | 0° (вниз с высоты), 15°, 30°, 45°, 60° (косые) |
| Обороты цели | полный круг вокруг каждой цели на каждой дистанции |
| Фон/освещение | ≥3 условия: солнце/пасмур/вечер; ≥2 фона (поле, лесополоса, грунт) |
| Помехи | похожие объекты рядом (другая машина рядом с джипом — тоже маркируем если другой класс) |
| **Кадров на класс (сырых)** | **≥200** (после аугментаций → ≥500) |
| Нарезка | видео → кадр каждые 0.5 с (`ffmpeg -i in.mp4 -vf fps=2 out/%05d.jpg` — скрипт дам) |
| **Калибровочные** | **200 произвольных кадров реальной съёмки отдельно** — для int8-квантизации (не маркируются!) |

Мелочи, которые решают качество:
- цель должна занимать от 20 px (далеко) до полкадра (близко) — весь диапазон
- избегай размытых кадров при нарезке (проверка резкости — скрипт дам)
- не мой снимок один объект с одной точки 200 раз — разнообразие важнее объёма

### 6.3 Маркировка (твоя часть, ~1–2 дня)

**Инструмент: CVAT** (self-host, docker — `docker compose up`, дам compose)
или labelstudio. Формат экспорта: **YOLO 1.1** (txt на кадр).

Правила: bbox вплотную к объекту; перекрытия <50% — всё равно маркируем;
сомнительный объект (не понятно ящик/не ящик) — не маркируем (шум хуже пропуска).

### 6.4 Конвейер (моя часть)

1. `scripts/prepare_dataset.sh` — валидация структуры, сплит 80/10/10,
   проверка резкости, отчёт по классам
2. `scripts/train_yolov8n.sh` — ultralytics YOLOv8n fine-tune
   (твой GPU если есть: 30 мин; иначе CPU ~ночь, или Colab-free)
   - база: `yolov8n.pt`, 4 класса, 100 epochs, imgsz=640, аугментации
     ultralytics (mosaic/hsv/flip — дискретные повороты настрою)
3. `scripts/eval_model.py` — mAP@0.5 на val + инференс на живом видео
   стенда (сравнение до/после)
4. `scripts/convert_rknn.py` — уже есть; добавлю калибровочный датасет
   в конвертацию (int8 quantization with real data)
5. Правка софта: `[inference] labels = ["tent","box","fuel_truck","jeep"]`
   из конфига вместо зашитых COCO_LABELS (POC 5.2-3, ~2 ч)

### 6.5 KPI модели (гейт G1)

| Метрика | Цель | Текущее (COCO) |
|---|---|---|
| mAP@0.5 (val сплит классов стенда) | ≥ 0.85 | — |
| Детекций на живом кадре при conf 0.45 | ≤ 10 (полезные) | ~1000 (over-detect) |
| FPS на RK3588 (SHM-путь) | ≥ 20 | 12 (упор в размер ответа) — с ≤10 дет станет ≥25 |
| Падение mAP int8 vs fp16 | ≤ 5 % | ~30 % (dummy-калибровка) |

Fine-tune с реальной калибровкой закрывает сразу три проблемы:
over-detect (#7), conf=0.50-артефакт (#8), и разгружает трекер
(Hungarian на 64-треках вместо 1000+).
